# Корпус Терна 0.10 — ревизия исходников и исправления (20.11.2026)

## Что именно просмотрено

В качестве базы использован действующий проект 0.10 с реальными PNG и XML, файлы исходников 0.10.1 и 0.10.3, журнал третьей сборки GitHub Actions (#3, commit 9916c78). Проанализированы 23 C#-файла, 17 XML-файлов и их 489 именованных определений, система билдов/чертежей/стоимости/производства, NPC фракции, наземные и орбитальные крепости, 7 семейств турелей, CE-боеприпасы, стили и графические пути. Проверка текстур охватила 1704 PNG, в том числе 4 стороны направленных построек и 113 привязок на каждую из 2 палитр.

Все числа относятся **к статической проверке**. Игра и DLL здесь не запускались; актуальный CE 1.7 у пользователя не установлен в этой среде.

## Исправлено в едином пакете

1. **CS0115 / несовместимая сигнатура `PostDeSpawn(Map)`** в `ThornMoats.cs` и `TurretRetrofits.cs` — использована безопасная уборка на `PostDestroy`, для живых объектов периодическая чистка реестра без сканирования карты.
2. **CS1061 / `next.def.building`** в `TurretRetrofits.cs` — чтение непосредственно `next.building`.
3. **CS1061 / `ThingDef.verbs`** в `ThornFortresses.cs` — убрано обращение к несуществующему полю.
4. **Старый тест отвергал новую систему турелей** — `tests_static_08.py` обновлён под два безопасных периодических обработчика карт.
5. **Создание бесплатного оружия/брони через обычный Bill_Production** — запрет выдачи изделия без соответствующего сохранённого чертежа, валидной конструкции и оплаченного пользовательского производственного заказа (`Events.cs`). Это защитный барьер на выходе из рецепта; не следует путать его с уже реализованным полноценным доставлением ресурсов.
6. **Сборка скрывала ошибки следующих этапов** — GitHub Actions теперь отдельно выполняет целостность проекта, проверку XML и проверку графики, и затем запускает компилятор даже при падении одной из этих проверок. После успешной компиляции требуется успешность всех структурных проверок, прежде чем паковать установочный архив.
7. **Новые контрольные проверки** `tests_project_integrity.py`: дубликаты имён Def, ссылки на собственные классы C#, графические пути, известные ошибки API 1.7, защита от бесплатного крафта.

## Серьёзные незакрытые проблемы проекта (не выдаём за готовую игру)

**P0 — мешает подтверждению исправности модификации:**

- Код не прошёл полного цикла `dotnet build -> установка -> запуск RimWorld 1.7 + конкретная сборка CE`. Наиболее вероятный следующий этап проверки — новая CI-сборка после интеграции этого пакета. До неё нельзя гарантировать отсутствие последующих C# ошибок или ошибок дефиниций CE.
- CE 1.7 существует в нескольких сторонних сборках; уникальные внешние `AmmoSet_*`, `Bullet_*`, особенности классов CE и Harmony-хуки требуют проверки с конкретно установленной сборкой. Статический тест подтверждает только внутренние ссылки.
- Универсальный держатель оружия передаёт произвольное оружие CE через отражение полей; это **экспериментальный адаптер**, а не подтверждённая совместимость с любым оружием персонажа.

**P1 — дефекты/незавершённые механики, которые дадут неверный игровой результат даже после успешной компиляции:**

- Лазер — сейчас фактически энергетический снаряд CE, а не непрерывный луч с гарантированным попаданием.
- ПТУР не имеет подтверждённого наведения на движущиеся цели; РСЗО/лазер/бластер и CE-баллистика требуют игрового тестирования.
- Модули оружия не все отражаются в руках пешки, а модули надетой брони не рисуются по индивидуальной сборке; бело-красная модульная палитра пока не подключена к каждому динамическому слою C#.
- Материалы оружия и брони списываются мгновенно при оформлении заказа из доступных запасов карты, без физической доставки. Полный жизненный цикл списаний и возвратов при разрушении верстака не проверен.
- Для брони CE модификация защиты отдельных частей тела зависит от наличия и точного совпадения хука `CombatExtended.ArmorUtilityCE.PartialStat(Apparel, StatDef, BodyPartRecord)`; если хук не установится, необязательные шлем/перчатки/ботинки средней брони не обеспечат корректное отсутствие защиты в своих зонах.
- `CompThornTrench` меняет TerrainDef на воду, а интерфейс прохода/водного контура и удаление рва через минификацию не проверены: возможен неправильный путь или невосстановленная исходная поверхность.
- Для орбитальных заводов-крепостей Odyssey проверены только собственные XML и код генерации, но **не подтверждено**, что игра действительно создаёт поселения на орбитальной карте и корректно застраивает безопасные участки.

**P2 — производительность и стабильность:**

- Нет замеров TPS на больших колониях и с CE/другими модами. Некоторые `StatPart` вызываются при частых запросах характеристик пешек. Нельзя считать проект доказанно оптимизированным по TPS.
- Разработка производства в конструкторе и CE-режимы огня пока сопоставляются по техническим дефам; динамические магазин/режим требуют игры для проверки.
- Старые тесты `tests_static.py`, `tests_static_06.py` и `tests_static_07.py` жёстко рассчитывают на прежние версии каталога/разрешения изображений: для проверки версии 0.10 используются актуальные `tests_static_09.py`, `tests_visuals_10.py` и `tests_project_integrity.py`, а не устаревшие тесты ранних версий.

## Как применять этот пакет

1. Распаковать ZIP из сообщения в **корень локального Git-репозитория** с заменой одноимённых файлов. Он содержит **только изменённые** исходники, workflow, Python-тесты и этот отчёт, а не повторно все текстуры.
2. В GitHub Desktop Summary написать: `Audit fixes: CE build errors, bill validation, full checks`.
3. Выполнить `Commit to main`, затем `Push origin`. Изменение `.github/workflows/build.yml` запускает GitHub Actions автоматически.
4. Только **зелёная сборка** даст установочный ZIP в Artifacts; дальше нужны реальные тесты RimWorld + CE. Ошибки C# и графики теперь собираются информативнее в одном запуске.

Нельзя использовать этот пакет как готовый игровой мод: он является набором исправлений исходного проекта. Не нужно повторно загружать 1704 графических PNG.
