# Корпус Терна — аудит Player.log и Player-prev.log, проект исправления 0.11.1

## Источник и срез

RimWorld **1.7.5014.1195**, Combat Extended **16.7.4.0**. Логи: `Player.log` (20.11.2026 23:31) и `Player-prev.log` (20.11.2026 21:25).

В последнем логе **749 записей ERROR**: 663 `Config error`, 38 `XML error`, 31 отсутствующая ссылка на определения, 9 исключений загрузки броневых ThingDef, 7 отсутствующих наборов графики боеприпасов, одно `NullReferenceException` при вызове `CombatExtended.AmmoInjector.InjectAmmos()`.

Эти числа не равны количеству независимых причин. Большинство ошибок — многократные проявления одного неверного шаблона, повторяющиеся для десятков серийных ThingDef.

## Изменения исходников

1. У девяти комплектов брони заменён несуществующий для этой среды `CompProperties_Quality` на обычный `Verse.CompProperties` с `compClass=RimWorld.CompQuality`. Их переплавка временно запрещена, пока ресурсные выходы не определены.
2. Энергетические AmmoDef снабжены обязательным `Class=CombatExtended.AmmoDef` вместо обычного `ThingDef`. Исправлен режим графики патронов (`Graphic_Single` для одиночных PNG).
3. `GrenadeHEAT` заменён на `RocketHEAT` в ПТУР; название должно быть проверено в живой CE 16.7.4.0.
4. Удалён недопустимый корневой тег `downloadUrl` из `About/About.xml`, не затрагивая ссылки зависимостей.
5. Убрано недопустимое поле `menuHidden` у турелей. Варианты модернизации исключены из обычного меню строительства, сохранив возможность использовать их из конструктора реконфигурации.
6. Серийные оружейные ThingDef переведены на базу `BaseGun` вместо `BaseHumanMakeableGun`, которая автоматически добавляла производственный рецепт без сметы. Сохранены заданные CE-вербы/компоненты, явно подключён компонент качества и одиночная категория `WeaponsRanged`.
7. Неопределённая переплавка оружия и турельных орудий выключена до появления честных рецептов разборки.
8. Переименованы пользовательские `ThingDef` с цифровым окончанием на имена с суффиксом `_Core`. Соответствующие ссылки обновлены в XML, C#, рецептах и тестах; глубина рва обновлена в C#. Это затрагивает сохранения!
9. Добавлены диапазоны воли и сопротивления к пленению бойцов фракции.
10. Две полностью непроходимые бетонные постройки помечены как сплошные препятствия (`fillPercent=1`). **Бронированные ворота при этом не превратились в рабочую дверь** — это отдельная функциональная задача.
11. Новый `tests_runtime_0111.py` и шаг в GitHub Actions проверяют первопричины ошибок из приложенных журналов до упаковки игрового ZIP.

## Что ещё НЕ исправлено и НЕ доказано

- В этом архиве **нет собранной DLL**. Необходим новый запуск GitHub Actions и тест загрузки игры.
- Исправление `NullReferenceException` внутри CE-инжектора пока является **гипотезой**, хотя корректный класс ammo-объектов непосредственно устраняет явную проблему их загрузки.
- Изменение имен ThingDef делает старые тестовые сохранения несовместимыми без миграции идентификаторов. Для 0.11.1 создайте новый тестовый мир и не перезаписывайте старые сейвы.
- Не проверены настоящие непрерывные лучи, точность лазера, наведение ПТУР, CE-бронепробитие новых снарядов, управление турелями, соединение рвов с водой, орбитальные и наземные заводы-крепости, TPS.
- Ошибка подсказки Ideology при наведении курсора **не зафиксирована отдельно** в присланных двух журналах; потребуется лог, снятый сразу после её воспроизведения, если повторится после исправления загрузки брони.
- Технический облик оружия в редакторе в виде разнесённой схемы утверждён в `CONSTRUCTOR_VISUAL_SPEC_RU.md`, но его отрисовка **не реализована** этим пакетом.
- Генераторы предыдущих версий (`build_defense_09.py` и т. п.) могут восстановить старые ошибки при ручном запуске; до их пересмотра не регенерировать определения этими скриптами. Автотест должен остановить публикацию ошибочного повторного результата.

## Установка патча

Распаковать архив **в корень локального GitHub-репозитория**, сохранить все каталоги, заменить существующие файлы; затем Commit/Push. GitHub Actions соберёт DLL и новый установочный ZIP. Пакет **не предназначен для прямого копирования в Mods**.
- `WeaponCatalog.WeaponDefName` и `WeaponCatalog.RecipeName` также изменены: к динамически создаваемым именам добавлен суффикс `_Core`, чтобы новый конструктор продолжил находить все переименованные предметы и рецепты. Добавлен автоматический тест на эту синхронизацию.
