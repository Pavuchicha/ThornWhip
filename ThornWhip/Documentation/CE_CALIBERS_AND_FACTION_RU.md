# Профили боеприпасов CE и устройство фракции (SOURCE 0.8)

## Конверсия калибра

Технологический принцип: при выборе нового патрона меняются патронник, подача, геометрия затвора и смета. Несущая оружейная основа остаётся того же семейства; 15 обычных слотов и три универсальных специальных остаются на месте.

| Семейство | Индекс C | Патрон CE | Особое требование |
|---|---:|---|---|
| Винтовка | 0 | 5,56×45 NATO | штатно |
| Винтовка | 1 | 7,62×39 Soviet | комплект конверсии в цене |
| Винтовка | 2 | 7,62×51 NATO | усиленные четыре узла |
| Автомат | 0 | 5,56×45 NATO | штатно |
| Автомат | 1 | 5,45×39 Soviet | комплект конверсии в цене |
| Автомат | 2 | 7,62×39 Soviet | усиленные четыре узла |
| Пистолет | 0 | 9×19 Parabellum | штатно |
| Пистолет | 1 | .45 ACP | усиленные четыре узла |
| Гранатомёт | 0 | 40×46 LV | без конверсии в текущей версии |

Физическая проверка усиления: слоты 0 (верхняя коробка), 2 (ствол), 3 (затвор), 9 (магазин). Усиленные варианты в текущем каталоге: индексы 1, 3, 4. Это не отдельные универсальные особые слоты. У штатных конверсий реальные баллистические изменения берутся из привязки к CE `AmmoSet`, не через фиктивный множитель бронепробития.

**Под капотом:** для сохранения конкретного CE `AmmoUser` и `defaultProjectile` без модификации общего ThingDef чертёж разрешает заранее зарегистрированные профили `TT_<Family>_R...B...M..._C...` (старые C0 без суффикса). Урон, тип снаряда, бронепробитие, гранатомётные эффекты, подбор используемого патрона рассчитываются CE. Изготовленное оружие сохраняет подробные модули в `CompWeaponDesign`.

## Одна фракция, два слоя

Фракция `TC_ThornCorps` имеет `requiredCountAtGameStart=1`, `maxCountAtGameStart=1` и `layerWhitelist=[Surface, Orbit MayRequire=Odyssey]`. Это разрешает поселения в обеих областях, но не заставляет генератор помещать объект в каждый слой. Проверка обязательна. Если одного слоя в новой игре нет, потребуется дополнительная интеграция с реальным генератором мира Odyssey.

Типы пешек: `TC_Operator`, `TC_Engineer`, `TC_Bulwark`. Используют тег `TC_Weapon` для оружия и `TC_Armor_Light`, `TC_Armor_Medium`, `TC_Armor_Heavy` для брони. Наборы тегов имеют `Inherit=False`, поэтому базовый Outlander не добавляет обычные винтовки/броню в списки выбора. Система случайных деталей выполняется *единожды при генерации* пешки и сохраняется на оружии/броне. Запасы патронов и контейнеры CE не подменяются.

Карта поселения при успешном хук-событии `MapGenerator.GenerateMap` дополняется стенами, бойницами/баррикадами и четыре строительными цехами с нашим рабочим столом. Обрабатывается только `Map.ParentFaction==TC_ThornCorps`. Другие поселения, включая базы чужих модов, не затрагиваются этим кодом. На орбитальной карте дополнительно сохраняются потенциальные вакуумные ячейки, но детектор пока эвристический, а не проверенный API проверки герметизации.

## Риски / проверки

- **Высокий приоритет:** компиляция `ThornWhip.dll` с .NET 10, API RimWorld 1.7 и фактически используемой версией CE; пока не выполнена.
- Тест появления поселений на обоих слоях в *новом* мире; слой Orbit может требовать отдельного worldgen-hook.
- Подтвердить подлинную выдачу штатных боеприпасов CE всем трём PawnKindDef и фактическое распределение брони.
- Постройки-крепости добавляются поверх результата генератора баз; схема не гарантирует полностью закрытый периметр из-за условия не разрушать существующие сооружения и космические зоны.
- Произвести CPU/TPS-профилирование на больших столкновениях; отсутствие `Tick`-скана само по себе не доказывает низкую нагрузку.
